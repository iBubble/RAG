## 二、两个案件的对比设计

| 维度 | CASE-A 焦糖瓜子 | CASE-B 卤香牛肉 |
|---|---|---|
| 案件类型 | 标签打假 | 标签 + 资质跨类 |
| 拆件数 | 2 件（T-1 + C-1） | **3 件（T-1 + C-1 + C-2）** |
| 指控数 | 3 项（香辛料/标准号/字符高度） | 2 项（执行标准/无证分装） |
| 通道走向 | 全部走瑕疵 → 责令改正 + 不予立案 | C-1 瑕疵 / C-2 须现场核查 |
| 举报人画像 | 疑似职业索赔（触发 S3-S8） | 正常维权（无 S 信号） |
| S9 红线 | 边界情形（**应判未达**） | 不触发 |
| 管辖 | 销售者所在地（普通管辖） | **平台内经营者新规**（令121号第13条） |
| 赔偿 | 不支持十倍（瑕疵） | 不支持十倍（瑕疵）+ 调解终止 |
| 关键考点 | 法律认知错误识别 + 瑕疵判定 + S9 边界 | 拆件 + 平台新规 + A3 禁自动化 |

**测试目的**：
- 案件 A 测**轻处理**通道（瑕疵 → 不立案）
- 案件 B 测**重处理**通道（拆件 + 现场核查 + 管辖新规）
- 两个案件合起来，覆盖了 80% 以上的来件处理路径

## 三、覆盖的规则点

### 3.1 通用规则（两个案件都涉及）

| 规则 | 案件 A | 案件 B |
|---|---|---|
| 拆件方法论（以法律关系为单元） | ✓ | ✓ |
| 混合件分类（M-CR / M-CRP） | ✓ | ✓ |
| 来件三型请求分类（民事/行政/程序） | ✓ | ✓ |
| 管辖判定 | ✓ | ✓ |
| 令49号第37条瑕疵六情形 | ✓ | ✓ |
| 食安法第148条十倍赔偿（148 条但书排除） | ✓ | ✓ |
| 令2号第20条不予立案 | ✓ | ✓（仅 C-1） |
| 令121号第23条终止调解 | ✓ | ✓ |
| 令121号第36条举报人保密 | — | ✓ |
| 令121号第28条举报线索要求 | ✓ | ✓ |
| S1–S8 恶意识别信号 | ✓（5 项触发） | ✓（0 项触发） |
| S9 红线识别 | ✓（**边界判定**） | — |

### 3.2 案件 A 专属考点

- **法律认知错误识别**：「香辛料属食品原料非添加剂」——智能体必须**超越举报人的法条引用**，独立判断事实
- **瑕疵逐项审查**：指控 1 不成立 + 指控 2/3 成立 → 不得"全有全无"
- **S9 边界情形**：施压表述 + 法定额度 + 真实举报 → 智能体**不得**机械升级为红线
- **不予奖励**：货值小 + 属瑕疵类 → 不构成《重大违法举报奖励办法》所称重大违法

### 3.3 案件 B 专属考点

- **平台内经营者新规**：令121号第13条「平台公示地址」管辖（**新规变更**）
- **跨法律关系拆件**：C-1（标签）与 C-2（资质）证据、责任主体、依据条款均不同
- **A3 禁止自动化**：C-2 涉嫌无证分装，必须现场核查，**不得**自动定性
- **首负责任制告知**：商家"代卖"抗辩不成立，T-1 调解通知中应明确告知
- **新线索分流**：举报人提供"无实际经营场所" → 增项转核查轨
- **举报人保密**：调解必需信息除外

## 四、测试使用方法

### 4.1 端到端测试

1. 启动智能体后，**仅提供**以下输入：
   - 案件 A：`01-举报信/投诉举报信.md` + `02-证据材料/`（5 个文件）+ `03-录音/`（2 个文件）
   - 案件 B：同上结构（5 个文件 + 2 个文件）
2. 不向智能体**预提示**"这是测试数据"或"以下是正确答案"
3. 智能体应自动完成：分类 → 拆件 → 要素抽取 → 路由 → 法规匹配 → 文书生成
4. 与本目录的 `预期处理结论.md` 逐项对照评分

### 4.2 分模块测试

| 模块 | 测试输入 | 期望输出 |
|---|---|---|
| 要素抽取 | 案件 A 全部材料 | 抽取 § 6.4 字段表的所有字段 |
| 拆件 | 案件 B 全部材料 | T-1 + C-1 + C-2 三件，附 SP-XX / JX-XX 引用 |
| 瑕疵判定 | 案件 A 附件 3 | 香辛料不成立、其余 2 项瑕疵 |
| 管辖判定 | 案件 B 附件 7 | 光泽县局；引用令121号第13条 |

| 文书生成 | 任一案件 | 至少 9–11 份，引用条款项具体到「第 X 条第 X 款第 X 项」 |

## 五、数据生成方式（可复用）

```bash
# 图像（购物小票/产品照片/订单截图/聊天截图）
python _tmp/gen_evidence.py

# 录音（中文女声 edge-tts）
python _tmp/gen_audio.py
```

依赖：
- pillow
- edge-tts（联网调微软 Azure TTS，国内可能需代理）
- 微软雅黑/宋体 字体（`C:\Windows\Fonts\msyh.ttc` 等）
- Python 3.13

修改案件信息后，**重新运行**上述脚本即可生成新的测试数据包。

## 六、注意事项

1. **本数据包是虚构数据**：人物、店铺、SC 编号、订单号、电话号码、地址均为虚构，如有雷同纯属巧合。
2. **录音由 TTS 合成**：非真实人声，但内容与文字稿严格一致。
3. **图片由程序生成**：文字清晰可控，便于 OCR 校验；但视觉真实感弱于真实照片。
4. **不要上传到任何公开仓库**：含身份证号片段、电话片段、地址片段，**仅限本地测试使用**。
5. **法规版本**：所有引用均以 2026-04-15 施行的令121号、2022-03-15 施行的令49号、2022 年修正的令2号为准。GB 7718 已发布 2025 年新版，过渡期安排须单独核对。
