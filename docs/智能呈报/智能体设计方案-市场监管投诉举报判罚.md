# 市场监管投诉举报判罚智能体设计方案

> **适用场景**：处理 12315 平台/来信/来访的投诉举报件，辅助执法人员完成分诊、路由、要件核查、裁量建议与文书生成
> **法规基准**：《市场监督管理投诉举报处理办法》（总局令第121号，2026年4月15日施行）、《市场监督管理行政处罚程序规定》（令2号）、《行政处罚法》（2021修订）
> **配套资料**：《法律法规全文库》（40部）、《市场监督管理部门处理投诉举报文书式样》（2026年4月，10种）、《市场监督管理行政处罚文书格式范本》（2021修订，56种）

---

## 〇、结论先行

1. **混合件（投诉+举报同信）的判罚规则是一句话**：《投诉举报处理办法》第9条——"向市场监督管理部门同时提出投诉和举报，或者提供的材料同时包含投诉和举报内容的……**对投诉和举报予以分别处理**"。注意：是"**分别处理**"，不是"合并处理"，也不是"择一处理"。

2. **智能体不能做成"自动判罚机"，必须做成"双轨办案助手"**：投诉轨（民事调解）与举报轨（行政查处）的程序、期限、文书、法律后果完全不同，智能体的第一价值是**把混合件拆对、把期限管住、把文书套准**，而不是替人下处罚决定。

---

## 一、混合件的判罚规则（核心问题）

### 1.1 法律依据（新旧对照）

| 规则 | 旧《暂行办法》（令20号→61号修正） | 新《办法》（令121号，2026-04-15施行） |
|---|---|---|
| 混合件处理 | 第7条 分别处理 | **第9条** 分别处理（条文内容不变，序号后移） |
| 投诉材料要求 | 第9条 | **第10条**（新增：对材料真实性负责；争议"事实"改为"事实依据"；**第3款可要求提供身份证明材料**） |
| 不予受理 | 第15条（6项） | **第16条（7项）**：新增"提供虚假材料、冒用他人名义、拒不配合核验真实身份信息" |
| 生活消费判断 | 未列举具体因素 | **第17条新增**：四类判断因素＋兜底 |
| 终止调解 | 第21条（45个工作日） | **第23条**（**60个自然日**；新增主体资格灭失、涉嫌骗取赔偿/敲诈勒索等） |
| 举报形式要件 | 第24条（具体线索） | **第28条**（具体线索＋**相应的事实依据**） |
| 重复举报 | 无 | **第35条新增**：同一人就同一事实重复举报同一被举报人的，**不再另行处理**；补充新事实的可合并处理，从最后一次举报起重新计算期限 |
| 立案告知 | 第31条第2款（5个工作日内告知是否立案） | **已删除**（立案是过程性决定）→ 这正是 2026 版文书式样**删除**《举报立案告知书》《举报不予立案告知书》的原因 |
| 反滥用 | 无 | **第7条第2款**（不得滥用权利牟取不正当利益）＋**第42条**（夹带/掉包/造假/敲诈勒索→移送公安机关） |

### 1.2 混合件"分别处理"的五个不同

| 维度 | 投诉轨（民事调解） | 举报轨（行政查处） |
|---|---|---|
| 性质 | 消费者权益争议的**行政调解** | 对涉嫌违法行为的**行政查处** |
| 处理依据 | 办法第16-26条 | 办法第27-35条 ＋ 令2号处罚程序规定 |
| 期限起算 | 收到投诉之日起 **7个工作日** 内决定是否受理（第14条） | 收到线索之日起 **15个工作日** 内核查决定是否立案（令2号第18条） |
| 办理期限 | 受理之日起 **60个自然日** 内调解（第23条） | 立案之日起 **90日** 内作出处理决定（令2号第64条） |
| 结果形式 | 调解书 / 终止调解决定书 | 立案→调查→处罚/不予处罚/移送 |
| 告知义务 | **必须**告知受理与否，并告知理由与消保法第39条其他途径（第15条） | **仅在法律、法规、规章明确规定时**告知处理结果（第34条，已删除统一立案告知） |
| 救济途径 | 调解不成→民事诉讼、仲裁（第25条） | 对处罚决定→行政复议、行政诉讼 |
| 保密要求 | 需向被投诉人披露调解必需信息 | 举报人信息严格保密（第36条，**混合件例外**：为组织调解所必需的信息可披露） |

### 1.3 混合件标准作业流程（SOP）

```
第1步 拆件登记
  ├─ 投诉部分 → 《投诉登记表》（式样一），单独编号
  └─ 举报部分 → 《举报登记表》（式样二），单独编号
     ※ 同一份材料拆出两条记录，但保留"同一来源"关联字段

第2步 双线并行
  ├─ 投诉轨：7个工作日受理审查（第16条7项 + 第17条5因素生活消费判定）
  │          → 受理：组织调解（60个自然日）
  │          → 不予受理：告知理由 + 消保法第39条其他途径
  └─ 举报轨：15个工作日核查（令2号第18条）
             → 立案：进入56种处罚文书流程（90日内决定）
             → 不予立案：填写不予立案审批表（无需单独告知，除非实名+法定情形）

第3步 证据共用、结论分立
  ├─ 同一事实的调查证据（现场笔录、检验报告）可共用
  └─ 但法律文书必须分别作出：调解书 ≠ 处罚决定书

第4步 关键红线
  ├─ 【调解不免除处罚】对消费者权益争议的调解，不免除经营者依法应当承担的
  │   其他法律责任（第23条第2款）
  │   → 即使双方达成调解协议、经营者已赔偿，举报轨仍应继续查处并处罚
  └─ 【处罚不替代赔偿】行政处罚（罚款、没收）不免除经营者的民事赔偿责任
      → 消费者的损失仍须通过调解或民事诉讼解决

第5步 合并告知（可选）
  └─ 告知可以合并送达，但内容须分列投诉结果与举报结果两部分
```

### 1.4 其他典型情形的判罚矩阵

| # | 情形 | 判罚规则 | 依据 |
|---|---|---|---|
| A | **纯投诉**（仅主张退赔） | 走调解，不作处罚；调解中发现违法线索的，转举报轨另行核查（第23条） | 办法第16-26条 |
| B | **纯举报**（仅反映违法） | 走核查立案→处罚；不组织调解，不处理民事赔偿 | 办法第27-35条 + 令2号 |
| C | **混合件** | 分别处理（见 1.2/1.3） | 办法**第9条** |
| D | **一行为违反多个法条**（法条竞合） | **择一重**：同一违法行为违反多个法律规范应当给予罚款的，按**罚款数额高**的规定处罚；不得给予两次以上罚款 | 行政处罚法**第29条** |
| E | **多个违法行为** | 分别裁量、**合并执行**（罚款累加；吊销许可、责令停产停业等按最重执行） | 行政处罚法第29条（不重复罚款）+ 各单行法 |
| F | **连续/继续状态违法** | 视为**一个**违法行为（如长期无照经营），但持续性可作为从重情节 | 行政处罚法第29条 |
| G | **单位违法** | **双罚制**：罚单位 + 罚直接负责的主管人员和其他直接责任人员（如食安法第135条从业禁止） | 各单行法 |
| H | **超过追责时效** | 2年内未被发现的不予处罚；涉及**公民生命健康安全、金融安全且有危害后果**的延长至**5年** | 行政处罚法**第36条** |
| I | **新旧法交替** | **从旧兼从轻**：适用违法行为发生时的规定；但处理时新法处罚较轻或不认为违法的，适用新法 | 行政处罚法**第37条** |
| J | **涉嫌犯罪** | **必须移送**司法机关并抄送检察院，不得以罚代刑 | 行政处罚法第27条 + 《行政执法机关移送涉嫌犯罪案件的规定》第3条 |
| K | **重复举报** | 同一举报人、同一事实、同一被举报人 → **不再另行处理**；补充新事实的可合并，从最后一次举报起重算期限 | 办法**第35条** |
| L | **疑似恶意索赔/滥用权利** | ①第17条五因素判断是否属"生活消费"→ 不属则不予受理；②第16条虚假材料/冒用名义/拒不配合核验 → 不予受理；③涉嫌夹带、掉包、造假、敲诈勒索 → **终止调解 + 移送公安机关** | 办法**第7条第2款、第16条、第17条、第23条、第42条** |
| M | **不属市场监管职责** | 不予受理但**须告知理由**及消保法第39条其他途径；属其他部门职责的告知向有权限部门提出 | 办法第2条、第15条第2款、第34条 |
| N | **平台内经营者被投诉** | 由其**平台公示地址所在地**县级局 或 平台经营者住所地县级局处理；未公示或公示地址无法联系的 → **平台经营者住所地**县级局 | 办法**第13条** |
| O | **广告类举报** | **同案管辖**：广告发布者所在地局先核查是否违法，构成违法的对广告主、广告经营者同案管辖；管辖异地主体确有困难的才移送 | 办法**第32条第1款** |

## 二、智能体架构设计

### 2.1 三条设计原则（决定成败）

| 原则 | 含义 | 反例（禁止） |
|---|---|---|
| **规则用代码，判断用模型** | 期限计算、管辖判定、条款匹配、竞合择重等**确定性逻辑一律硬编码**；语义理解、要素抽取、说理草拟交给 LLM | 让 LLM 数工作日、算罚款倍数 |
| **可溯源，零幻觉** | 每一条法律依据必须能定位到知识库中的条、款、项原文，并标注效力状态与生效日期 | 模型凭记忆生成"第XX条" |
| **人在回路** | AI 输出一律为"**建议稿**"；涉及人身罚、吊销许可、大额罚款的，强制转人工＋集体讨论 | AI 直接生成并送达处罚决定书 |

### 2.2 七层架构

```
L0 接入层   多模态解析：12315结构化数据 / 文本 / 扫描件OCR / 图片 / 录音转写
            └→ 统一案件对象（Case Object）
L1 分诊层   核心：投诉/举报/混合件/非受理事项 四分类 + 要素抽取 + 置信度
            └→ 规则特征（是否有具体诉求/是否要求查处） + LLM 语义判定
L2 路由层   双轨分派 + 管辖判定 + 重复件检测 + 时效校验
            └→ 输出：轨道标签、管辖机关、期限表、是否重复
L3 知识层   法规 RAG（实体法/程序法/裁量基准 三层索引，条级切片）
            └→ 条级检索 + 效力状态校验 + 版本比对（从旧兼从轻）
L4 推理层   构成要件匹配 + 法条竞合择重 + 裁量因子打分 + 幅度区间
            └→ 输出：违法行为定性 + 建议处罚种类与幅度 + 说理要点
L5 生成层   56种处罚文书 + 10种投诉举报文书的模板填充
L6 质控层   法条校验 / 期限倒计时 / 程序合规检查表 / 敏感度分级 / 人工签发门禁
L7 回流层   复议诉讼结果、审核退回意见回流，持续优化规则与提示词
```

### 2.4 知识库设计（决定智能体上限）

三层索引，全部**条级切片 + 结构化元数据**：

| 索引 | 内容 | 元数据字段 | 用途 |
|---|---|---|---|
| **A 实体法库** | 禁止性规范 + 罚则（食安法、产品质量法、药品管理法、广告法、价格法……） | 法条号、违法行为类型标签、构成要件、处罚种类、幅度区间、生效/废止日期 | 定性 + 幅度 |
| **B 程序法库** | 处罚法、令2号、办法121号、行政强制法 | 环节、时限、文书编号、强制/任意 | 期限 + 文书 |
| **C 裁量基准库** | 总局指导意见 + 各省级局裁量基准表 | 省份、违法行为、从轻/一般/从重档次、对应情节 | 档次判定 |

**切片策略**：以"条"为最小单位，每条附 `law_id + article_no + effective_from + effective_to + tags`。检索时对命中条做**效力校验**（行为发生日 vs 处理日），自动执行"从旧兼从轻"（处罚法第37条）。

> 现有资产可直接使用：`法律法规全文/` 40 部 Markdown 全文已具备条级结构，可脚本化切片入库，无需重新采集。缺口是**省级裁量基准**与**反垄断/广告/价格**等领域的单行法，需补充。

### 2.5 分诊提示词骨架（L1 核心）

```text
# 角色
你是市场监督管理投诉举报分诊助手。依据《市场监督管理投诉举报处理办法》
（总局令第121号）判断材料性质，输出结构化 JSON。

# 判定标准（硬规则，不得自行发挥）
判定为【投诉】的充分条件：
  - 主体是消费者，且为生活消费需要购买、使用商品或接受服务；
  - 与经营者发生消费者权益争议；
  - 提出具体民事请求（修理/重作/更换/退货/补足数量/退款/赔偿损失）。
判定为【举报】的充分条件：
  - 反映经营者涉嫌违反市场监管法律、法规、规章的线索；
  - 通常表现为要求查处、罚款、没收、吊销、奖励，或不提出个人诉求。
同时满足两者 → 【混合件】。
仅属咨询、政府信息公开、行政复议、信访、纪检监察检举 → 【非受理事项】。

# 输出要求
1. 必须输出 evidence_spans，每个判断引用原文片段并给出字符偏移，便于人工复核；
2. 置信度 < 0.7 时，type 标记为"待人工确认"，不得自动路由；
3. 不得编造材料中没有的事实；要素缺失时输出 null 而非推测。

# 输出格式
{...同 2.3 的 triage 结构...}

# 少样本示例（3-5 条，务必覆盖混合件与恶意索赔特征）
```

### 2.6 质控层（Guardrails）——最容易被忽略但最关键

| 检查项 | 规则 | 触发动作 |
|---|---|---|
| 法条幻觉 | 输出的每条引用在知识库中不存在 / 已废止 / 生效日晚于行为发生日 | **拦截**，标记并要求重写 |
| 期限逾期 | 任一法定期限剩余 ≤ 2个工作日 | 红色预警推送办案人 |
| 程序缺环 | 未告知即处罚 / 应听证未听证 / 应法制审核未审核 / 应集体讨论未讨论 | **拦截**，不得进入下一环节 |
| 择重错误 | 法条竞合时未取罚款数额高的规定 | 提示并给出正确条款 |
| 时效错误 | 超过2年/5年追责时效仍建议处罚 | **拦截** |
| 敏感分级 | 涉及人身自由罚、吊销许可、责令停产停业、较大数额罚款 | 强制转人工 + 提示需集体讨论 |
| 反滥用审慎 | 命中第17条任一因素即建议不予受理 | **降级为提示**（第17条要求个案综合判断，不得一刀切） |
| 保密合规 | 输出中包含举报人身份信息 | 自动脱敏，混合件调解必需信息除外 |

## 三、落地路线图

| 阶段 | 范围 | 交付物 | 价值 |
|---|---|---|---|
| **MVP（2-4周）** | L0-L2 分诊+路由 + L6 期限提醒 | 混合件自动拆件、双轨期限倒计时、管辖建议 | 直接解决基层"分不清、超期多"两大痛点 |
| **V2（+4周）** | L3-L4 法条检索 + 裁量建议 | 构成要件匹配、法条引用可溯源、裁量档次建议 | 减少定性错误与量罚不当 |
| **V3（+4周）** | L5 文书生成 + 完整质控 | 56+10 种文书草稿自动填充、程序合规检查 | 卷宗质量提升，复议撤销率下降 |
| **V4（持续）** | L7 回流学习 | 复议诉讼结果回流、规则库迭代 | 越用越准 |

**建议 MVP 先做三件事**：混合件拆件、期限看板、文书清单生成——这三件事**规则确定、价值最高、风险最低**，能让一线立刻感受到减负，同时把"自动判罚"这个高风险能力留到 V2/V3 并始终保留人工签发门禁。
