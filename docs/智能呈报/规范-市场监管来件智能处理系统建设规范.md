# 市场监督管理来件智能处理系统建设规范

## Agent Development Specification for Market Supervision Intake Processing

**文档编号**：MSA-SPEC-2026-001
**版本**：V1.0
**适用范围**：市场监督管理部门投诉举报及各类来件的智能化处理系统（含智能体/Agent）的需求定义、规则设计、流程设计与开发实施
**法规基准**：《市场监督管理投诉举报处理办法》（总局令第121号，2026年4月15日施行）、《市场监督管理行政处罚程序规定》（总局令第2号）、《中华人民共和国行政处罚法》（2021年修订）

> **条款引用说明**：本规范中标注"令121号第X条"的，为总局令第121号《市场监督管理投诉举报处理办法》正式文本条款号。因该办法系在原《暂行办法》基础上新增6条、修改22条后全面修订，条款序号整体后移，凡未逐条核验者，本规范仅描述规则内容并标注"〔序号待核验〕"。**实现时必须以令121号正式文本为准，并在知识库中以"法规标识+版本号+条款号"为主键存储，禁止硬编码条款序号。**

## 第一章 总则

### 1.1 目的
统一市场监督管理部门各类来件的接收、分诊、拆件、路由、办理、告知、归档标准，为智能处理系统（智能体）的建设提供可执行的业务规则、数据规范与质控要求。

### 1.2 基本原则

| 编号 | 原则 | 要求 |
|---|---|---|
| P1 | **分别处理** | 同一来件包含不同性质事项的，必须拆分后分别处理（令121号第9条） |
| P2 | **一事一件** | 一个独立的法律关系构成一个处理事项，独立编号、独立计时、独立结案 |
| P3 | **程序法定** | 所有处理环节、期限、文书必须有明确法律依据，无依据不得增设环节 |
| P4 | **人在回路** | 智能体输出为"建议"，实体性决定由执法人员作出并承担法律责任 |
| P5 | **可溯源** | 每一结论须可回溯至来件原文片段与法规条款原文，全程留痕 |
| P6 | **过罚相当** | 处罚种类与幅度应与违法事实、性质、情节、社会危害程度相当 |

### 1.3 规范性引用文件
- 《市场监督管理投诉举报处理办法》（总局令第121号）
- 《市场监督管理行政处罚程序规定》（总局令第2号）
- 《市场监督管理行政处罚文书格式范本》（2021年修订版，56种）
- 《市场监督管理部门处理投诉举报文书式样》（2026年4月，10种）
- 《中华人民共和国行政处罚法》《行政强制法》《消费者权益保护法》及其实施条例
- 《行政执法机关移送涉嫌犯罪案件的规定》
- 各领域单行法（食品安全法、产品质量法、药品管理法、广告法、价格法、特种设备安全法等）

## 第二章 术语与定义

| 术语 | 定义 |
|---|---|
| **来件** | 市场监督管理部门通过任何渠道接收到的、需要作出响应的信息载体 |
| **事项** | 来件经拆分后形成的最小处理单元，对应一个独立的法律关系 |
| **分诊** | 判定来件性质、抽取要素、识别风险，并确定处理轨道的过程 |
| **拆件** | 将包含多个法律关系的来件拆分为若干独立事项的过程 |
| **并件** | 将多个来件或事项合并为一个处理单元的过程 |
| **轨道** | 按事项性质划分的处理通道（调解轨/查处轨/答复轨/移送轨/归档轨） |
| **期限** | 法律法规规定的、办理某一环节的时间上限 |
| **门禁** | 系统强制要求人工介入方可继续的环节 |
| **自动化等级** | 智能体在某一环节可自主决策的程度（A0-A3，见第9.3条） |

## 第四章 拆件规则（核心）

### 4.1 拆分原则

**总原则：以"法律关系"为拆分单元。**

一个独立的法律关系 = 特定主体 + 特定事实 + 特定诉求 + 特定法律后果。任一要素不同且法律后果独立可分的，应拆分为独立事项。

### 4.2 拆分触发条件表

| 规则ID | 触发条件 | 是否必须拆分 | 拆分维度 | 依据 |
|---|---|---|---|---|
| **SP-01** | 同时含投诉内容与举报内容 | **必须** | 按诉求性质拆为 C 事项 + R 事项 | 令121号第9条 |
| **SP-02** | 投诉涉及多个经营者（如消费者投诉平台与商家） | **必须** | 按被诉主体拆分，分别登记、分别调解 | 调解需双方合意，主体不可混同 |
| **SP-03** | 举报涉及多个被举报主体 | **必须** | 按被举报主体拆分；同一主体的多个违法行为可并案 | 令2号第19条（管辖与立案审查以主体为单位） |
| **SP-04** | 举报涉及多个独立的违法行为（不同时间、不同行为、不同法条） | 建议拆分（可并案调查） | 按违法行为拆分；并案调查的，在一份处罚决定书中分别裁量、合并执行 | 处罚法第29条 |
| **SP-05** | 不同事项的管辖机关不同 | **必须** | 按管辖拆分，属本部门管辖的留办，不属的移送/分送 | 令121号第12-13条、令2号第14、17条 |
| **SP-06** | 同时含咨询与投诉/举报 | **必须** | 咨询部分转答复轨，其余按性质处理 | 令121号第39条〔序号待核验〕 |
| **SP-07** | 同一来件同时包含应予受理与不予受理的内容 | **必须** | 可受理部分立为事项，不可受理部分单独作出不予受理告知并说明理由 | 令121号第15条 |
| **SP-08** | 不同事项分属不同监管领域且由不同内设机构办理 | 建议拆分 | 按领域拆分，内部分送 | 内部分工 |

### 4.3 拆分算法

```
Step 1  文本切分：按语义段落切分来件为 N 个片段
Step 2  片段标注：对每个片段标注 (性质, 主体, 事实, 诉求, 领域)
Step 3  聚类合并：
        同性质 AND 同主体 AND 同一法律关系 → 合并为一个事项
        不同性质 OR 不同主体 OR 管辖不同     → 拆分为独立事项
Step 4  编号赋权：为每个事项分配事项编号，记录同源关联
Step 5  要素继承：来件级要素（来源、收到时间、附件）继承至各事项
Step 6  冲突检测：同一证据被多个事项引用的，标记为"证据共用"，物理存储一份
Step 7  人工确认：置信度 < 0.7 的拆分结果转人工确认（门禁 G-01）
```

### 4.4 并件规则

| 规则ID | 情形 | 处理方式 | 依据 |
|---|---|---|---|
| **MG-01** | 两名以上消费者基于**同一争议**投诉**同一经营者** | 经投诉人同意，按**共同投诉**处理，可书面推选两名代表人 | 令121号〔对应原暂行办法第11条，序号待核验〕 |
| **MG-02** | **同一举报人就同一涉嫌违法事实重复举报同一被举报人** | **不再另行处理** | 令121号**第35条** |
| **MG-03** | 同一举报人以**补充新的事实**为由再次举报 | **可以合并处理**，从收到**最后一次举报**之日起重新计算处理期限 | 令121号**第35条** |
| **MG-04** | **不同举报人**举报同一被举报人的同一违法事实 | 并案处理，统一核查、统一决定是否立案，**分别告知**各举报人 | 令121号第34条 |
| **MG-05** | 同一当事人的多个违法行为已被分别立案 | 可并案调查、并案审理；在一个处罚决定书中**分别裁量、合并执行** | 处罚法第29条 |

### 4.5 拆件后的处理约束

1. **独立计时**：每个事项独立计算法定期限，不得因其他事项办理而顺延
2. **独立结案**：每个事项独立结案、独立归档，但卷宗可合并装订
3. **证据共用**：同一事实的证据（现场笔录、检验报告、询问笔录）在事项间共享，原件存于主事项卷宗，其余事项存复制件并注明出处
4. **告知合并、结论分立**：告知文书可以合并送达，但内容必须分列各事项的处理结果
5. **保密隔离**：举报事项的举报人信息，对投诉事项的被投诉人**不得披露**（令121号第36条但书：仅为组织调解所必需的信息除外）

## 第五章 处理路由

### 5.1 轨道模型

```
                       ┌─→ 调解轨（C类）：受理审查 → 调解 → 调解书/终止调解
                       │
来件 → 分诊 → 拆件 ────┼─→ 查处轨（R类）：核查 → 立案 → 调查 → 告知 → 决定 → 执行 → 结案
                       │
                       ├─→ 答复轨（Q类）：直接答复 → 归档
                       │
                       ├─→ 移送轨（X/G/A/J类 + 无管辖权件）：移送/分送 → 告知
                       │
                       └─→ 归档轨（N类）：登记 → 归档
```

### 5.2 路由决策表

| 优先级 | 条件 | 轨道 | 说明 |
|---|---|---|---|
| 1 | 涉嫌犯罪（达到移送标准） | 查处轨 + **行刑移送门禁** | 不得以罚代刑，处罚法第27条 |
| 2 | 不属市场监管部门职责 | 移送轨 | 告知理由 + 其他途径（第15条第2款） |
| 3 | 属市场监管职责但本机关无管辖权 | 移送轨（内部） | 移送有管辖权的机关，不得再自行移送 |
| 4 | 属咨询/信访/信息公开/复议/纪检检举 | 移送轨（外部） | 告知相应途径 |
| 5 | 属投诉且符合受理条件 | 调解轨 | 7个工作日内受理 |
| 6 | 属投诉但不符合受理条件 | 调解轨（不予受理） | 不予受理 + 说明理由 + 消保法第39条途径 |
| 7 | 属举报且有线索和事实依据 | 查处轨 | 15个工作日内核查 |
| 8 | 属重复举报（MG-02） | 归档轨 | 不再另行处理 |
| 9 | 无效件 | 归档轨 | 登记备查 |

## 第六章 全流程处理规范

### 6.1 环节总表

| 序 | 环节 | 输入 | 输出 | 时限 | 文书/记录 | 自动化等级 |
|---|---|---|---|---|---|---|
| S1 | 接收登记 | 原始来件 | 来件编号、登记记录 | 即时 | 案件来源登记表 | A0 |
| S2 | 分诊 | 来件内容 | 分类、要素、置信度、风险标记 | ≤1个工作日 | 分诊记录 | A1 |
| S3 | 拆件 | 分诊结果 | 事项清单、编号、证据关联 | ≤1个工作日 | 拆件记录 | A1 |
| S4 | 材料核验 | 事项材料 | 材料完整性结论 | 即时 | 限期提供材料通知书 | A0/A1 |
| S5 | 管辖判定 | 事项 | 管辖机关、依据 | 即时 | 分送/移送文书 | A1 |
| S6 | 受理/立案审查 | 事项 | 受理决定 / 立案决定 | 投诉7工作日；举报15工作日 | 投诉受理/不予受理决定书；立案/不予立案审批表 | **A3（人工）** |
| S7 | 办理 | 已受理/立案事项 | 调解结果 / 调查结论 | 调解60自然日；办案90日 | 调解书 / 现场笔录、询问笔录、检验报告、案件调查终结报告 | A2 |
| S8 | 裁量与审核 | 调查结论 | 处罚建议、裁量理由 | 审核10工作日 | 案件审核/法制审核表 | A1 |
| S9 | 告知 | 拟处理意见 | 告知书 | 决定前 | 行政处罚告知书 | A1 |

### 6.2 关键环节详述

#### S4 材料核验
- **投诉**：须提供姓名、电话号码、通讯地址等**真实身份信息**、被投诉人名称地址、**相应的消费者权益争议事实依据**（令121号第10条）
- 对材料真实性负责；市场监管部门为**核验真实身份**可要求提供身份证明材料（第10条第3款）
- 材料不全/存疑 → 发出《限期提供身份证明材料通知书》（文书式样四）；**逾期未提供或提供虚假材料的，不予受理**（第10条、第16条）
- **举报**：须提供涉嫌违法的**具体线索**及**相应的事实依据**（令121号第28条）；可以匿名，但实名举报方享有告知与奖励资格

#### S6 受理审查（投诉轨）
**不予受理七情形**（令121号第16条）：
1. 投诉事项不属市场监管部门职责，或本行政机关无处理权限
2. 法院、仲裁机构、市场监管部门或其他行政机关、消费者协会或依法成立的其他调解组织**已受理或处理过同一争议**
3. **不是为生活消费需要**购买、使用商品或接受服务，或**不能证明与被投诉人之间存在消费者权益争议**
4. 除法律另有规定外，投诉人知道或应当知道权益受侵害之日起**超过三年**
5. 未提供第10条第1款、第11条规定的材料，或**提供虚假材料**
6. **冒用他人名义**或**拒不配合核验真实身份信息**
7. 法律、法规、规章规定不予受理的其他情形

**"生活消费"判断五因素**（令121号**第17条**）：
| 因素 | 具体表现 |
|---|---|
| 消费行为特征 | 购买商品的数量、次数、频率与商品保质期或通常消费习惯**明显不符** |
| 投诉行为特征 | 同一投诉人对同一经营者、同类商品服务、同类问题**短期内大量投诉**；或不同投诉人**恶意串通**集中投诉 |
| 争议真实性 | 不能证明存在已实际购买商品/接受服务、自身权益已实际受侵害的**真实消费关系** |
| 身份真实性 | 多人使用同一手机号码、通讯地址，姓名与手机号无法匹配，**有冒用嫌疑** |
| 兜底 | 设区的市级以上局可结合本地实际细化判断因素 |

> ⚠️ **实现红线**：第17条要求**结合个案综合判断**。系统命中任一因素时，
> **只能输出提示（自动化等级 A1）**，不得自动作出不予受理决定，
> **不得一刀切**将特定群体拒之门外。

**受理告知义务**：不予受理的，**还应当告知不予受理的理由**和《消费者权益保护法》第39条规定的其他途径（令121号第15条）。

#### S6 立案审查（举报轨）
**立案四要件**（令2号第19条，须同时满足）：
1. 有证据**初步证明**存在违反市场监管法律、法规、规章的行为
2. 依据市场监管法律、法规、规章**应当给予行政处罚**
3. **属于本部门管辖**
4. 在**给予行政处罚的法定期限内**

**可以不予立案四情形**（令2号第20条）：
1. 违法行为轻微并及时改正，没有造成危害后果
2. 初次违法且危害后果轻微并及时改正
3. 当事人有证据足以证明**没有主观过错**（法律、行政法规另有规定除外）
4. 依法可以不予立案的其他情形

#### S7 办理（查处轨）证据要求
证据种类与对应文书（2021范本）：书证、物证、视听资料、电子数据、证人证言、当事人陈述、鉴定意见、勘验笔录和现场笔录。
- 电子数据须记录**完整性校验值**（文书12）
- 检验鉴定须载明**资质、依据、方法、过程、明确结论**（文书30）
- 先行登记保存：7个工作日内作出处理决定，逾期自动解除（处罚法第56条）

#### S9-S11 告知与决定
- **告知是效力要件**：未告知的处罚决定**不能成立**（处罚法第38条、第44条）
- 告知内容：拟作出处罚的**内容、事实、理由、依据**
- **不得因当事人陈述、申辩或要求听证而给予更重的处罚**（令2号第58条）
- **听证范围**（处罚法第63条）：较大数额罚款 / 没收较大数额违法所得、较大价值非法财物 / 降低资质等级、吊销许可证件 / 责令停产停业、责令关闭、限制从业 / 其他较重处罚
- **法制审核 + 集体讨论**：情节复杂或重大违法案件，决定前**必须法制审核**（令2号第50条），拟给予行政处罚的**必须负责人集体讨论**（令2号第54条）

| **L4** | 推理层 | 构成要件匹配、定性、竞合择重、裁量因子打分、幅度区间、时效校验 | 处置建议 + 说理要点 |
| **L5** | 生成层 | 文书模板填充（56+10种）、证据清单、期限表 | 文书草稿 |
| **L6** | 质控层 | 法条校验、期限预警、程序合规检查、敏感分级、门禁控制、脱敏 | 拦截/预警/放行 |
| **L7** | 回流层 | 复议诉讼结果回流、人工退回原因归因、规则与提示词迭代 | 优化建议 |

### 9.2 自动化等级定义

| 等级 | 名称 | 定义 | 适用环节 |
|---|---|---|---|
| **A0** | 全自动 | 系统自主完成，无需人工确认 | 编号生成、期限计算、形式校验、重复检测、文书清单生成、脱敏 |
| **A1** | 建议-确认 | 系统给出建议与理由，人工确认后生效 | 分类、拆件、管辖、条款匹配、裁量档次、不予受理/立案建议 |
| **A2** | 辅助生成 | 系统生成内容供人工采纳修改 | 要素抽取、说理草拟、文书正文、调查提纲 |
| **A3** | 禁止自动化 | 必须由执法人员作出决定，系统不得代替 | **立案/不予立案、处罚/不予处罚决定、移送司法机关、终止调解、听证举行、决定书签发** |

### 9.3 门禁清单（强制人工介入）

| 门禁ID | 触发条件 | 要求 |
|---|---|---|
| **G-01** | 分诊或拆件置信度 < 0.7 | 转人工确认后方可继续 |
| **G-02** | 拟作出吊销许可、责令停产停业、责令关闭、限制从业 | 人工审核 + 法制审核 + 集体讨论 |
| **G-03** | 拟罚款达到本地"较大数额"标准 | 人工审核 + 告知听证权 |
| **G-04** | 涉嫌犯罪 | 人工研判 + 负责人批准移送 |
| **G-05** | 拟不予立案 / 不予行政处罚 | 人工审核并书面说明理由 |
| **G-06** | 拟适用第17条"非生活消费"不予受理 | **必须人工综合判断**，系统仅提示 |
| **G-07** | 拟终止调解（尤其涉第42条） | 人工决定 |
| **G-08** | 期限剩余 ≤ 2个工作日 | 强制提醒 + 记录催办 |

### 9.4 提示词规范（L1 分诊层）

**必备要素**：
1. **角色与依据**：明确依据令121号第3条定义判定
2. **硬规则**：列出投诉/举报/咨询的充分条件，禁止模型自行发挥
3. **输出约束**：
   - 必须输出 `evidence_spans`：每个判断引用来件原文片段 + 字符偏移
   - 置信度 < 0.7 → `type="待人工确认"`，不得自动路由
   - 要素缺失输出 `null`，**禁止推测**
4. **少样本**：至少覆盖 纯投诉 / 纯举报 / **混合件** / 咨询 / 疑似恶意索赔 五类
5. **反幻觉约束**：不得引用未在知识库中出现的法条；不得编造事实

**禁止事项**：
- 禁止让模型计算工作日、倍数罚款、时效天数（一律由代码计算）
- 禁止让模型直接输出确定性处理结论（应输出"建议"+依据+置信度）

## 第十二章 质控规范

### 12.1 强制校验项（任一不通过即拦截）

| 编号 | 校验项 | 规则 |
|---|---|---|
| QC-01 | 法条存在性 | 输出的每条引用在知识库中存在且状态为"现行有效" |
| QC-02 | 法条时序 | 引用条款的生效区间覆盖违法行为发生日 |
| QC-03 | 告知前置 | 作出处罚决定前必须有告知记录 |
| QC-04 | 听证权利 | 属第63条情形的，必须有听证权告知记录 |
| QC-05 | 法制审核 | 属令2号第50条情形的，必须有法制审核通过记录 |
| QC-06 | 集体讨论 | 属令2号第54条情形的，必须有集体讨论记录 |
| QC-07 | 时效校验 | 未超过处罚法第36条追责时效 |
| QC-08 | 竞合择重 | 法条竞合时取罚款数额高者 |
| QC-09 | 申辩不加重 | 处罚幅度不得因当事人申辩而高于告知时的拟处罚 |
| QC-10 | 期限合规 | 所有环节在法定期限内完成 |

### 12.2 红线清单（绝对禁止）

1. ❌ 系统自动生成并送达任何对外生效的法律文书
2. ❌ 系统自动作出立案/不立案、处罚/不予处罚、移送、终止调解的终局决定
3. ❌ 依据第17条因素**自动**拒绝受理（须人工综合判断）
4. ❌ 向被举报人泄露举报人身份信息（混合件调解必需信息除外）
5. ❌ 以调解协议替代行政处罚，或以行政处罚替代民事赔偿
6. ❌ 对涉嫌犯罪案件"以罚代刑"
7. ❌ 引用知识库中不存在或已失效的法条
8. ❌ 删除或修改审计日志

### 12.3 脱敏要求
- 举报人姓名、联系方式、地址在对外文书中默认脱敏
- 混合件中为组织调解所必需的，经审批后向被投诉人提供**最少必要信息**
- 涉及商业秘密、个人隐私的信息，未经审批不得进入训练语料
