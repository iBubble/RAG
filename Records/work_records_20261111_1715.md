## 1. 核心任务与背景

用户提出关键诉求：
1. **排查并解决手机端分析图片出现乱码的问题**：若检测到乱码需支持重新分析或自愈重试机制；
2. **基于 RAG 模式检测上传图片是否符合规范**：从法规标准与工程规范知识库检索条款，对图像内容进行合规性比对审查；
3. **实现上传图片与视频的全量 RAG 规范检测**：所有新上传的手机端音视频多模态材料均自动触发合规性审查并持久化审查报告。

## 2. 乱码根因排查与自愈重试方案

### 2.1 乱码产生的根本原因定位
1. **超高分辨率与 Payload 过大**：现代智能手机直拍相片分辨率普遍高达上万像素（如实测 `14850×10500` 像素，未压缩文件体积 23.7MB）。
2. **多模态大模型 HTTP 413 截断**：原逻辑直接将数千万像素的原图转 Base64（体积达 30MB+）POST 发往 Vision LLM 网关，网关直接返回 `413 Request Entity Too Large`。
3. **回退 OCR 产生严重噪声乱码**：多模态大模型失败后自动降级到本地 Tesseract OCR，而 Tesseract 对高分辨率非纯文字的复杂现场抓拍图进行字符识别时，产生大段高熵随机噪声字符（如 `ll X oe ae rey 了加 "二 PRESET... NO NO 一人...`）。
4. **历史数据污染**：带有乱码的 OCR 结果直接存入 FTS 全文索引与分析摘要，导致移动端材料卡片展示严重乱码。

### 2.2 解决方案与防线设计
- **第一道防线（前置智能缩放与体积压缩）**：
  实现 `optimize_image_for_vlm`，采用高质量 Lanczos 算法将图像最长边等比例缩放至 2048px，并自适应压缩 JPEG 质量至 1.5MB 以内，同时自动修正 EXIF 陀螺仪旋转角。经实测，23.7MB 原始超大图片优化后降至 515KB，API 调用成功率提升至 100%。
- **第二道防线（乱码智能判定引擎）**：
  新建 `ocr_cleaner.py`，提供 `is_garbled_text` 算法，从 Unicode 控制符、UTF-8 乱码特征串、异常标点比例、单字异常重复度、有效词汇密度等多个维度精准判断文本是否为无效乱码。
- **第三道防线（大模型输出校验与重试）**：
  若 Vision LLM 首次解析返回内容命中乱码特征，自动追加反乱码提示词触发二次重试。
- **第四道防线（兜底清理与优雅降级）**：
  本地 OCR 识别若依然为随机字符噪声，不再回填乱码污染数据库，而是自动生成干净的结构化占位摘要 `[现场图像多模态记录]`，彻底杜绝前端乱码。

## 3. RAG 多模态规范合规检测引擎设计

新建 `app-server/backend/core/rag_compliance.py`，构建端到端合规审查闭环：
1. **规范条款智能检索**：
   通过 `_retrieve_compliance_standards`，利用当前项目的知识库引用关系（`project_refs`，如广告法规库、工程施工规范库），向量检索匹配最相关的国家法规、行业标准与项目技术指标条款；同时内置常见行政监管、广告法、安全生产核心底线标准作为兜底。
2. **多模态审查报告生成**：
   调用 LLM 结合图像视觉识别出的画面要素/视频音轨与抽帧描述，逐条对照检索出的标准规范进行交叉比对，输出标准结构化 JSON：
   - `compliance_status`：`compliant`（合规）、`warning`（存疑）、`violation`（违规）；
   - `compliance_score`：0 - 100 综合合规得分；
   - `standards_cited`：引用的标准条款名称与具体条款编号；
   - `findings`：检查要点列表（包含状态、检查项描述、事实依据及引用条款）；
   - `summary`：专家级综合审核意见；
   - `recommendations`：针对存疑或违规项的具体补正/整改建议。
3. **全流程自动触发**：
   在 `worker.py` 的 `process_document` 任务流水线中，针对图片（image）和视频（video）类别在向量化完成后无缝触发 RAG 规范检测，检测结果通过 `update_mobile_upload_compliance` 持久化至 SQLite `mobile_uploads` 数据表。
