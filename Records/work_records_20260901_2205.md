# 2026-09-01 22:05 行政处罚文书范本全量错位修复与案件来源登记表高保真重构

## 修改背景
Master 反馈在 AI 表格模块中选择“市场监督管理行政处罚文书范本”下的“1.案件来源登记表”时，内容呈现为封面与总体说明，与原版 PDF 范本完全不一致，并要求核查修正其余全部表格。

## 根本原因排查
1. **起始页截断缺陷**：PDF 共 80 页（Page 0 封面、Page 1 总体说明、Page 2~3 目录、Page 4~79 共 76 页正文对应 56 项文书）。旧抽取脚本未过滤前导页，在遍历目录页时误判正文起始，将封面与总体说明提取为了“1.案件来源登记表”，将目录提取为了“2.指定管辖通知书”，致使真实的第 1、2 号文书丢失。
2. **文书漏失与前移**：“25.封条”未被识别致后续 26~43 项前移错位；“44.当场行政处罚决定书”第 2 页被当成“45.行政处罚决定书”；“54.卷宗封面”、“55.卷内文件目录”、“56.卷内备考表”全部丢失，系统内原本仅存 52 项且全面错位。

## 核心修改内容
1. **高精度定制模板扩充 (`custom_templates.py`)**：
   - 依据 PDF 截图像素级还原 `CASE_SOURCE_REGISTER_HTML`（1.案件来源登记表），设计 7 列严格对称的 Colgroup 网格系统，100% 还原“案源提供人”（监督检查人/投诉举报人/移送交办部门）、“当事人”、“案源内容/处理意见”等复杂多级单元格与签字盖章区域；
   - 增加 `SEAL_HTML`（25.封条）、`DOSSIER_CATALOG_HTML`（55.卷内文件目录）、`DOSSIER_NOTE_HTML`（56.卷内备考表）等定制模版。
2. **切分引擎与页码映射升级 (`re_extract_tables.py`)**：
   - 构建 `PUNISHMENT_DOC_RANGES`，精确映射 56 项文书在 Page 4~79 的页码区间，杜绝封面与目录干扰；
   - 新增 `extract_punishment_docs` 专用提取管道，多页公文自动合并段落与落款，含表公文保留黑框与排版。
3. **数据重构与服务热重载**：
   - 执行脚本全量清洗并更新 `local_data/ai_templates.json`，文书总数准确达到 56 项；
   - 在 `GenRAG-Server` 容器内完成 `pm2 reload genrag-backend` 热重载生效。
4. **前台历史草稿覆盖排查与前端重新构建**：
   - 定位前台为何呈现旧内容：前台 `AITablePanel.tsx` 带有优先加载已存草稿的逻辑，因用户此前打开过，导致磁盘 `/Volumes/macData/GenRAG_Files/data/documents/a179bfa2f2ef/` 下存有含旧说明的历史草稿（`doc_d9cilor2m.json`），前台每次进入都优先读取旧草稿；
   - 清理旧草稿：删除含错误说明的残留历史草稿；
   - 前端增加防御与功能：`AITablePanel.tsx` 增加对“总体说明”等脏数据的自动过滤抛弃机制，并新增【重置模板】（`RotateCcw`）按钮；
   - 重新打包前端产物：在容器内完成 `npm run build`，生成 `index-v4-D6xjHQM-.js`，并 `pm2 reload genrag-frontend`、`genrag-gateway` 热重载。
