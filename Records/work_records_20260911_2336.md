# 工作记录 - 2026-09-11 23:36

## 任务背景
在 MacBook Pro (M4 Max) 上运行系统时，用户反馈在电脑重启或关盖休眠唤醒后，前台频繁弹出红色告警横幅「🚨 大载荷独立磁盘阵列（RAID）异常脱机！系统已降级运行...」。需要建立自动重试机制，彻底杜绝重启或休眠恢复后产生的误报并实现无感秒级自愈。

## 根本原因定位
1. **宿主机 Cron 执行环境 PATH 缺失**：macOS crontab 执行环境仅含 `/usr/bin:/bin`，无法寻址位于 `/usr/local/bin/docker` 的 Docker 命令，导致 `storage_watchdog.sh` 无法在后台重启失效容器。
2. **休眠唤醒瞬态延迟与零重试断言**：macOS 唤醒外置磁盘就绪需 2~5 秒，后端 `core/watchdog.py` 单次瞬态判定失败便立刻置为只读脱机模式。
3. **前端缺乏状态缓冲与自动重试**：前端收到单次脱机状态即全屏显示阻断横幅。

## 核心改造落地
1. **宿主机自愈加固** [storage_watchdog.sh](file:///Users/gemini/Projects/Own/RAG/scripts/storage_watchdog.sh)：
   - 显式声明全局 PATH（`/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin...`）；
   - 增加探测双重确认（间隔 1.5 秒二次复验），避免瞬态抖动；
   - 增加日志轮转防膨胀保护。
2. **macOS 原生守护机制**：
   - 注册系统级 LaunchAgent [com.gemini.storage_watchdog.plist](file:///Users/gemini/Library/LaunchAgents/com.gemini.storage_watchdog.plist)（20 秒高频巡检、开机唤醒即启）；
   - 更新用户 crontab 注入标准 PATH 作为双重热备保障。
3. **后端防抖重试** [watchdog.py](file:///Users/gemini/Projects/Own/RAG/app-server/backend/core/watchdog.py) 与 [generate.py](file:///Users/gemini/Projects/Own/RAG/app-server/backend/api/generate.py)：
   - 连续 3 次探测失败（间隔 2 秒，约 6 秒缓冲）才确认脱机；
   - 脱机保护状态下以 3 秒高频探活加速恢复；
   - `llm_status` 接口引入请求即时探测与秒级退出保护模式。
4. **前端平滑防抖与交互增强** [App.tsx](file:///Users/gemini/Projects/Own/RAG/app-server/frontend/src/App.tsx)：
