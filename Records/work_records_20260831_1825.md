# 工作记录 - 2026-08-31 18:25

## 任务背景
在 MacBook Pro (M4 Max) 运行环境下，关盖休眠或恢复后，Docker Desktop 的 VirtioFS / gRPC-FUSE 会导致外置磁盘挂载句柄失效（在容器内部出现悬空 inode 导致 `No such file or directory`），触发 RAG 系统后端脱机警报与只读保护。用户要求建立自动化自愈机制，防止关盖休眠唤醒后反复出现此故障。

## 方案选型与技术决策
经方案对比与用户确认（参考 [技术决策记录.md](file:///Users/gemini/Projects/Own/RAG/技术决策记录.md) 中的 ADR-002），选择 **方案 1：宿主机统一守护巡检与自愈机制**。

## 实施详情
1. **编写自愈守护脚本** [storage_watchdog.sh](file:///Users/gemini/Projects/Own/RAG/scripts/storage_watchdog.sh)：
   - 自动检测宿主机 `/Volumes/macData` 基准目录是否正常；
   - 矩阵式巡检 `GenRAG-Server` 和 `RAG-Server` (LawRAG) 的运行状态及容器内挂载点；
   - 发现“宿主机磁盘正常但容器内挂载断裂”时，触发带 60s 防抖保护的安全自愈重启；
   - 输出详细自愈审计日志至 `/tmp/storage_watchdog.log`。
2. **挂载自动化系统调度**：
   - 将 `storage_watchdog.sh` 写入宿主机 macOS 的用户 crontab（`* * * * *` 每分钟自动巡检）。
3. **架构与决策文档同步**：
   - 在 [技术决策记录.md](file:///Users/gemini/Projects/Own/RAG/技术决策记录.md) 中正式补充归档 ADR-002。
